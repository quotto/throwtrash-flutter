# AI取り込み完了通知の FCM 化

## 背景

AI取り込みの完了/失敗通知をアプリ内の処理完了後にローカル通知として表示していたが、iOS ではバックグラウンド移行後に Dart の継続処理がサスペンドされ、一定時間を超えると通知表示がフォアグラウンド復帰まで遅延する。

調査結果として、API 送受信自体が完了しているケースでも、`await` 後に実行されるローカル通知処理はバックグラウンド実行時間の制約を受ける。このため、AI取り込みの完了通知はアプリ側のバックグラウンド継続実行ではなく、サーバーからの FCM によって受信する方針へ変更する。

## 要件

1. スケジュール検索APIへのリクエスト時に、検索条件に加えてクライアント情報を送信する。
2. クライアント情報は `/Volumes/extend/project/trash-schedule-search/docs/openapi.yaml` の `SearchClient` 仕様に従う。
3. iOS では以下の形式で `client` を付加する。

```json
{
  "address": "東京都新宿区西新宿2丁目",
  "client": {
    "platform": "ios",
    "fcm_token": "FCM_REGISTRATION_TOKEN"
  }
}
```

4. 郵便番号検索の場合も既存の `postal_code` に同じ `client` を付加する。
5. `client.platform` は `ios` または `android` とし、iOS では検索終了時に API 側で FCM 通知ジョブが enqueue される前提とする。
6. `client.fcm_token` は既存の FCM トークン登録/更新の仕組みを利用して取得する。
7. API 側の FCM 通知対応は完了済みとし、アプリ側では API リクエストへのトークン付加と既存受信処理の維持を行う。
8. 受信した FCM メッセージの表示、および通知タップ時の挙動は現行通りとする。
   - フォアグラウンド受信時はローカル通知として表示する。
   - 通知タップ時はアプリのルート画面へ戻る。
9. 検索リクエスト実行時のバックグラウンドタスク化は不要とし、AI取り込み処理から削除する。
10. 調査用に追加した API 呼び出し迂回と遅延通知だけを行うデバッグ処理は削除する。
11. サーバー FCM とアプリ内ローカル通知の二重通知を避けるため、検索 API 応答後に AI取り込み完了/失敗をローカル通知する処理は廃止する。
12. API 応答に基づく取り込み結果の保存、画面上で表示する取り込みメッセージ、既存のデータ置換処理は維持する。

## トークン取得方針

- `FcmService.refreshDeviceToken()` を利用し、検索リクエスト直前に最新の FCM 登録トークンを取得する。
- 取得したトークンは `TrashApi.searchTrashSchedule` へ渡し、API リクエスト body の `client.fcm_token` に設定する。
- iOS で FCM トークンを取得できない場合、完了通知を保証できないため AI取り込み開始前に失敗として扱う。
- トークン登録済みという前提が実装上満たせない箇所が見つかった場合は、実装タスク内で既存の登録/保存処理の補修を行う。
- FCM トークンをログ出力する場合は、フルトークンを出さずマスクする。

## 完了条件

- 住所検索と郵便番号検索の API リクエスト body に `client.platform` と `client.fcm_token` が含まれること。
- AI取り込み実行時に既存の FCM トークン更新処理が呼び出されること。
- FCM トークン取得失敗時に検索 API が呼ばれず、ユーザー向けの失敗結果が保存/返却されること。
- AI取り込み処理が `BackgroundTaskService` に依存しないこと。
- API 呼び出しを迂回するデバッグ用遅延通知処理が残っていないこと。
- API 応答後の完了/失敗ローカル通知が廃止され、サーバー FCM 由来の受信通知だけが表示されること。
- FCM 受信時および通知タップ時の既存挙動が維持されること。
- 関連する単体テスト、Widget テストを更新し、`flutter analyze` と `flutter test` が成功すること。

## 注意事項

- FCM は通知到達を担うが、API 応答を受け取ってローカルデータへ反映する処理は現行通りアプリ側で行う。アプリが OS に終了された場合、HTTP 応答後のデータ反映は失われる可能性がある。
- 今回のスコープは完了通知の信頼性改善であり、検索結果を後から取得するジョブID方式や結果取得 API は対象外とする。
- 将来的に「通知受信後に必ず取り込み結果も反映済み」を保証する必要が出た場合は、API 側に検索ジョブIDと結果取得 API を追加する別 issue として扱う。
