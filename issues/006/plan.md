# issues/006 対応計画

## 対象

カレンダー画面の日付セルで、同一日に多数のゴミが対象になった場合の表示崩れを防ぐ。セル内表示は最大3種類に制限し、超過分は `...+{超過数}` として表示する。日付セルタップ時には詳細ダイアログを開き、対象日のすべてのゴミ名を確認できるようにする。

## 要求分析

### 機能要件

1. 日付セル内のゴミ名表示を最大3件に制限する。
2. 4件以上ある場合は3件だけ表示し、超過数を `...+{超過数}` で表示する。
3. 日付セルをタップしたら対象日の全ゴミ名を表示するダイアログを開く。
4. ダイアログにはセル内で省略されたゴミも含める。
5. ダイアログのタイトルには対象の年月日を `YYYY年MM月DD日` 形式で表示する。
6. 対象ゴミが0件の日付セルでもダイアログを開き、「出せるゴミはありません」と表示する。

### 非機能・品質要件

1. ゴミ表示上限は UI 表示だけに適用し、`CalendarModel` の全件データは保持する。
2. 既存の月移動、リロード、色表示、Semantics マーカーの挙動を壊さない。
3. 日付セルの高さ内に収まるよう、セル内部のレイアウトを安定させる。
4. 実装後は Widget テストと必要な単体テストを更新する。
5. `flutter analyze` と関連テストを通す。

## 現状整理

1. カレンダー画面は [lib/calendar.dart](../../lib/calendar.dart) の `CalendarWidget` で描画している。
2. 週行は `_flexibleRowWeek` で作られ、各日付セルは `Expanded > Column` として構成されている。
3. ゴミ名は `Wrap` 内で `trashList[index].length` 分だけ `Container` と `Text` を生成しており、表示数に上限がない。
4. 表示用データは [lib/viewModels/calendar_model.dart](../../lib/viewModels/calendar_model.dart) の `DisplayTrashData` と `calendarsTrashList` に全件保持されている。
5. 既存 Widget テストは [test/widget/widget_test.dart](../../test/widget/widget_test.dart) でカレンダー初期表示、曜日、セル内ゴミ名、Semantics マーカーを検証している。

## 前提

- セル内に表示する3件は、現在 `TrashDataServiceInterface.getEnableTrashList` から返る順序の先頭3件とする。
- `...+{超過数}` はゴミ名とは別の省略表示として扱い、ゴミ種別色は付けない。
- ダイアログのタイトルは対象日の実日付を算出し、`YYYY年MM月DD日` 形式で表示する。
- 前月/翌月の日付が同じカレンダー内に表示されるため、表示中の年月とセル位置・日付から対象年月日を判定する。
- 今回は UI 崩れ対策が目的であり、スケジュールデータの算出順や取得順は変更しない。

## 実装方針

1. `_flexibleRowWeek` の日付セル構築を小さな private Widget/helper に分離し、表示制限とタップ挙動を局所化する。
2. セル内表示用に `trashList[index].take(3)` を使い、全件リストはダイアログ表示用に保持する。
3. 超過数は `trashList[index].length - 3` で算出し、正の値の場合のみ `...+{超過数}` を表示する。
4. 日付セル全体を `InkWell` または `GestureDetector` でタップ可能にする。既存テーマとの整合を優先し、Material 配下で自然なタップフィードバックが出る実装を検討する。
5. 表示中の年月、週番号、セルの日付から対象の実日付を算出し、ダイアログタイトルに `YYYY年MM月DD日` 形式で表示する。
6. ダイアログは `showDialog` と `AlertDialog` を使い、対象日の全ゴミ名を縦に表示する。
7. 対象日のゴミが0件の場合は、同じダイアログ内に「出せるゴミはありません」と表示する。
8. ダイアログの閉じる操作は標準の閉じるボタン、または `TextButton` の「閉じる」で提供する。
9. テストしやすいよう、日付セル、省略表示、ダイアログに必要な `Key` または Semantics identifier を追加する。
10. 既存テストが依存している `Text` 数の期待値は、省略表示追加後の構造に合わせて更新する。

## 検証方針

```sh
flutter analyze
flutter test test/widget/widget_test.dart
flutter test
```

必要に応じて以下を手動確認する。

1. 1日に4種類以上のゴミを持つデータで、セル内表示が3件と `...+{超過数}` に収まる。
2. セル内の表示が日付セルを飛び出さない。
3. 対象ゴミがあるセルをタップすると、対象年月日タイトル付きの全件ダイアログが表示される。
4. 対象ゴミが0件のセルをタップすると、対象年月日タイトル付きのダイアログに「出せるゴミはありません」と表示される。
5. 前月/翌月の日付セルでも、ダイアログタイトルの年月日が正しい。
6. 月移動後も同じ表示制限とダイアログ表示が機能する。

## リスクと対応

- 既存テストがセル内の `Text` 数に依存している。  
  - 表示制限後の構造に合わせて期待値を更新し、超過表示の有無を明示的に検証する。
- 前月/翌月の日付が同じカレンダー内に表示されるため、ダイアログタイトルの年月が不正確になる可能性がある。  
  - 表示中の年月、週番号、セルの日付から実日付を算出し、前月/翌月セルも Widget テストで確認する。
- `Wrap` のままでは超過表示を含めてもセル内高さが安定しない可能性がある。  
  - 表示上限後も崩れる場合は `Column` と `Flexible`、固定高さ、`TextOverflow.ellipsis` を組み合わせてセル内に収める。
- セル全体をタップ可能にすると、PageView のスワイプと干渉する可能性がある。  
  - `InkWell`/`GestureDetector` の使用範囲を日付セル内に限定し、Widget テストと手動スワイプで確認する。

## 実装結果メモ

- `lib/calendar.dart` の日付セル描画を helper 化し、セル内のゴミ名表示を先頭3件に制限した。
- 4件以上ある場合は、セル内に `...+{超過数}` を表示するようにした。
- 日付セル全体を `InkWell` でタップ可能にし、`AlertDialog` で対象年月日タイトル、全ゴミ名、空日付メッセージを表示するようにした。
- ダイアログタイトルは表示ページの年月とセル位置から実日付を算出し、`YYYY年MM月DD日` 形式で表示する。
- Widget テストに、4件目以降の省略、ダイアログ全件表示、空日付の「出せるゴミはありません」表示を追加した。
- 自動検証として `fvm flutter analyze`、`fvm flutter test test/widget/widget_test.dart`、`fvm flutter test` は成功した。
