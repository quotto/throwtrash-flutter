# task2: 取り込み UseCase/Repository 実装

## 担当

developer

## 状態

完了

## 内容

- 既存データ全削除と API 結果登録を一連の処理として実装する。
- 反映成功時にリモート同期待ち状態へ更新する。
- 初回ダイアログ表示状態と一覧画面表示メッセージを保存する Repository を追加または既存 Repository に統合する。
- 取り込み結果をローカル通知へ渡す Service を追加する。
- 正常レスポンス反映後は、次にゴミ出し予定一覧画面を開いた際に取り込み完了メッセージを一度だけ表示する。
- エラー時は、次にゴミ出し予定一覧画面を開いた際にエラー内容を一度だけ表示する。
- 取り込み結果メッセージは正常系・異常系を判定できる状態で保存する。

## テスト

- 成功時に既存データが置き換わる。
- 反映後に同期状態が `SYNCING` になる。
- API エラー時に既存データが削除されない。
- 初回表示状態が実行・キャンセルどちらでも更新される。
- 一覧画面メッセージが保存・取得・表示後削除できる。

## 完了条件

- 対象単体テストが通る。
- 失敗時のデータ破壊がない。

## 実績

- 取り込み成功時に既存データを削除し、API 結果で置き換える処理を追加した。
- 取り込み成功後に同期状態を `SYNCING` に更新する処理を追加した。
- API エラー時は既存データを削除しないようにした。
- 初回ダイアログ表示済み状態と、一度きり取り込みメッセージを `TrashRepository` に追加した。
- 取り込み完了・失敗のローカル通知呼び出しを追加した。
- 成功時メッセージを `ゴミ出し予定を取り込みました` に更新した。
- `invalid_address` / `invalid_postal_code` / `unsupported_schedule` / `unknown` の固定メッセージを扱うようにした。
- ローカル通知本文をアプリ内表示メッセージと同じ内容に統一した。
- 対象テスト: `test/unit/usecase/trash_search_import_test.dart`

## 追加対応

- 取り込み結果メッセージの保存内容を、正常系・異常系を判定できる形式へ変更した。
- 既存の保存済みメッセージのみのデータがある場合も、表示後に削除できる互換性を維持した。
